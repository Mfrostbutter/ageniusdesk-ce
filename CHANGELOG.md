## [0.6.0] - 2026-09-06

### Added

- **`http.request` host bridge, trusted worker identity, and read-only endpoint grants.** Community modules that talk to an external service (the Proxmox module is the first) no longer hold a credential or open their own connection in any isolation mode. A module declares `capabilities.host.http.endpoints` (id, suggested base URL, auth shape naming a secret, methods, TLS policy); the operator confirms or overrides the base URL at install and chooses whether the module may change data (mutating methods are off by default); the host persists that as an effective endpoint revision in `data/module-endpoints.json`, pins the resolved IPs, and serves `POST /api/_host/http/request` for isolated workers while in-process modules call the same implementation directly. Per call the host enforces the granted endpoint and method, validates the relative path, keeps the URL on the consented origin, drops any worker-supplied `Authorization`/`Host`/`Cookie`, resolves the secret at call time, dials only a pinned address (a host that resolves elsewhere fails closed until re-pinned), disables redirects, caps the body at 5 MB, and allowlists the echoed response headers. Unknown `host` manifest fields now fail validation instead of being ignored. Every `/api/{community-module}/...` request also passes one identity middleware in every mode: inbound `X-AGD-*` headers are stripped (a browser cannot spoof the actor), the request is authorized by route class (reads at viewer, writes at operator, raised by the manifest's `routes` block but never lowered), and trusted `X-AGD-User`, `X-AGD-User-Id`, `X-AGD-Role`, and `X-AGD-Auth-Source` headers are stamped for the module to audit against. Settings > Modules gains an Upstream endpoints panel per community module (status, base URL, granted methods, pinned IPs, configure, re-pin) and the install consent modal shows each endpoint with its base URL and a separate change-data acknowledgement. The scanner reports declared bridge use and `verify_tls: false` endpoints as INFO and undeclared use as HIGH. The reverse proxy now closes the upstream stream on success, upstream failure, and client disconnect, with regression tests for XLSX and ZIP downloads. See [docs/specs/2026-09-05-host-http-bridge-build.md](docs/specs/2026-09-05-host-http-bridge-build.md).

- **Fleet Health contribution API: modules publish health rows into the pane.** A community module declares `contributes.fleet_health` (a subpath under its API prefix) and serves `{rows: [{label, status, metrics}]}`; the host collects every loaded contributor through one authenticated in-process call and merges the rows into Fleet Health, so module health (Proxmox cluster nodes first) renders next to the n8n instances. `GET /api/modules/fleet-health` returns the aggregated rows. The collector uses the same path in every isolation mode — an in-process module's mounted router or, under isolation, the reverse proxy to its worker — authorizing its own read with a per-process internal token that never leaves the process and that the identity middleware strips before a worker sees it. Each contributor has a short timeout and degrades independently: one broken or slow module is shown unreachable, never sinks the pane. Proxmox is the first contributor. This closes the second of the two host investments that gated the community-module quadrant.
- **Explicit MCP server ids.** `POST /api/mcp/servers` accepts an optional `id` (lowercase slug, 409 on collision; blank keeps the historical random hex). Fleet tool names embed the server id (`mcp__{id}__{tool}`), so a vault agent manifest can only reference a server whose id is chosen up front — a randomly generated id made pre-authored agents impossible to ship.
- **Fleet agents runnable over the public API, and MCP servers as fleet tools.** Two halves of the same loop: external systems can now start agent runs, and agents can now reach external tool planes. The public API (v1, `X-API-Key`) gains `GET /api/v1/agents` (read scope, the agent catalog), `POST /api/v1/agents/{agent_id}/runs` (trigger scope, start any registered agent by id), and `GET /api/v1/agents/runs/{run_id}` (read scope, full run record with the event log), so an n8n workflow or an outside platform can kick a triage without a dashboard session. The dashboard's `/triage` route and the new public route share one `runner.start()`, so single-flight (409 while a run is live), unknown-agent 404, and HITL parking behave identically at both doors; a fleet-less install answers 503. On the tool side, a vault agent's manifest can now declare `mcp__{server_id}__{tool_name}` names (the legacy `mcp:{server_id}:{tool_name}` colon form is accepted and normalized; wire names use underscores because Anthropic rejects tool names containing colons): the runner pre-warms a discovery cache from every MCP server configured in the assistant module before build, and the graph factory resolves those names into ready tool wrappers that execute through the assistant's MCP client — so server config, `$SECRET` bearer refs (e.g. an itops-mcp PSA token in the Secrets store), TLS posture, and audit stay in one place. Discovery failures are per-server and non-fatal, and `GET /api/agent-fleet/tools` now lists the discovered MCP tools alongside the built-ins for the agent builder.
- **Ticket sink: error groups become PSA tickets.** A new built-in module (`ticket_sink`, off by default) closes the loop between AgeniusDesk's error feed and a PSA: the first occurrence of an error group (instance, workflow, node, error type — the same grouping the Errors UI uses) files one ticket through an itops-mcp tool plane (`create_ticket`); a recurrence adds an Internal reply to that ticket (`add_ticket_reply`) rather than filing a duplicate; and once a technician closes the ticket the group re-arms, so the next occurrence opens a fresh ticket whose details reference the closed one. Replies are throttled (`AGD_TICKET_SINK_REPLY_INTERVAL_MIN`, default 15) so an error storm is one ticket plus a paced thread, not a queue flood, and backfilled or historical events (trace backfill, sync imports) never file tickets. Group-to-ticket state lives in a new `ticket_sink_state` table; the hook into error ingest is fire-and-forget so PSA latency or outage can never block or break storing an error. The MCP client carries the two failure modes a live phase gate surfaced on the platform side: FastMCP reports tool failures in-band (`result.isError` + text, not a JSON-RPC error), which the client raises on instead of treating a failed write as success, and a restarted MCP server answering a cached session id with 404 gets one transparent re-init-and-retry. Configure with `AGD_TICKET_SINK_ENABLED`, `ITOPS_MCP_URL`, `AGD_TICKET_SINK_CLIENT_ID`, and the `ITOPS_MCP_TOKEN` secret (env or Secrets store). Surfaces: `GET /api/ticket-sink/status`, `GET /api/ticket-sink/mappings`, and `POST /api/ticket-sink/test-fire` (operator role; runs a synthetic error through the sink synchronously and reports the action taken).
- **Trace backfill: rebuild lost traces from n8n's own execution history.** The span store was write-once: a rejected export, a receiver outage, or an instance that was never wired for OTel left a permanent hole no amount of waiting could fix (the motivating incident was a drifted ingest token that silently cost ~28 hours of traces). n8n, however, keeps every execution's per-node timing in its database independent of OTel, so the traces were never gone, only unreconstructed. A new synthesizer rebuilds them from `GET /api/v1/executions/{id}?includeData=true`: one `workflow.execute` root plus one `node.execute` child per node run, with real timings, parent edges from the upstream `source`, per-node status and errors, and input/output item counts, validated against a genuine exporter trace of the same execution. Rebuilt traces are first-class downstream: the waterfall renders them, cost enrichment prices them, and silent-failure detection runs on them (an incident raised from a rebuilt trace carries the execution's time, not ingest time, so it sorts into history instead of surfacing as breaking news; pass `detect_health: false` to skip detection on a deep rebuild). Ids are deterministic (`sha256("agd-backfill:{instance}:{execution}")`), so re-runs are idempotent, and every synthesized span is labeled `origin='backfill'`; real telemetry always outranks a reconstruction, arriving late it replaces the rebuilt trace, and a rebuild never overwrites a received one. Bounded by design: rebuilds refuse executions older than `AGD_OTEL_RETENTION_HOURS`, cap per run (`AGD_BACKFILL_MAX_EXECUTIONS`, default 500), and fetch with bounded concurrency (`AGD_BACKFILL_CONCURRENCY`, default 4). Surfaces: `GET /api/otel/backfill/preview` (counts what is rebuildable, no run-data fetches), `POST /api/otel/backfill/run` (operator role, live progress over the WebSocket), and a **Rebuild traces** action on Observe, offered right on the zero-span empty state where an operator lands after an outage. Because an instance or workflow set to `saveDataSuccessExecution=none` can never be rebuilt for successful runs, that condition is detected per instance and surfaced as a **Coverage gap** warning on the Instances panel and in the backfill preview, before recovery time instead of during. See [docs/specs/2026-08-14-trace-backfill-from-execution-history.md](docs/specs/2026-08-14-trace-backfill-from-execution-history.md).
- **Rename and API-key rotation on the Instances page.** An instance's name and its n8n API key were previously only changeable by re-entering the full record. The Instances panel now has a rename affordance next to the name (`PATCH /api/n8n/instances/{id}`, name only, nothing else touched) and a **Rotate** action next to the key hint (`POST /api/n8n/instances/{id}/rotate-key`). Rotation tests the new key against the instance, honoring its per-instance TLS setting, before anything is saved; a failed probe leaves the stored key untouched. The old key stays valid in n8n until revoked there, so rotation is a paste-test-save with no window where the dashboard holds a dead key.

### Fixed

- **HITL resume now carries the reviewer's identity.** `POST /api/agent-fleet/runs/{id}/resume` accepts a `by` field and threads it into the decision handed to the graph. Previously pydantic silently dropped it, so a gate that attributes the decision (the platform QBR agent records `reviewed_by` on the approved report) always logged the fallback `operator` no matter who approved. Absent stays empty, so existing graphs' `d.get("by") or "operator"` fallbacks are unchanged.
- **The built-in MCP server no longer disappears from fresh builds.** `mcp` was pinned as `>=1.2.0` with no ceiling, and the Docker build installed with `pip install ".[extras]"`, which ignores the committed `uv.lock` and re-resolves against PyPI every time. When `mcp` 2.0 removed `mcp.server.fastmcp`, any rebuild from that point silently failed to mount `dashboard_mcp` at `/api/mcp-dashboard`: 19 modules registered instead of 20, one WARNING line, app otherwise healthy. Two fixes, one for the instance and one for the class. The pin gains an upper bound (`mcp>=1.2.0,<2.0.0`, which is also what pydantic-ai's `fastmcp-slim` requires, so the langgraph extra keeps resolving), and the image now builds from the lockfile: `uv export --frozen --no-dev --no-emit-project` with one `--extra` per `AGD_EXTRAS` entry, installed with `pip install --require-hashes`. The shipped artifact is now the tested dependency set. `dashboard_mcp` also works against either SDK line now (`mcp.server.mcpserver.MCPServer` when present, `mcp.server.fastmcp.FastMCP` otherwise, with the transport options moved to `streamable_http_app()` where 2.0 put them), so the ceiling lifts cleanly once the ecosystem moves.
- **A built-in module that fails to load says so.** The loader treated a shipped built-in failing to import the same as an optional community module declining to load: a single WARNING, startup continues. A built-in failing is a degraded install, so it now logs at ERROR with the traceback, and any failed built-ins are re-stated right after the "Registered N modules" roster instead of scrolling past hundreds of lines earlier.
- **Observe distinguishes "no traces anywhere" from "none from this instance".** The header read the fleet-wide span count while the trace list and every metric scoped to the active instance, so an instance that had never exported a span still showed `Receiver on · 30 spans` next to `No traces yet. Run a workflow on the active instance.` Running workflows changed nothing and the view gave no reason why. The badge now counts the active instance (amber at zero, with a separate `+N other` pill for spans held for other instances), and `/api/otel/status` returns `instance_span_count` and `instance_name` alongside the fleet total. The setup instructions previously rendered only when the receiver was *off*; they now also render for the receiver-on-but-this-instance-unwired case, addressed to the instance by name and with the real endpoint filled in instead of a `<this-host>:<port>` placeholder.

## [0.5.0] - 2026-08-13

### Upgrade notes

- **The assistant now asks before it acts.** State-changing tool calls (trigger a workflow, activate, import, write a note, any MCP write tool) come back as an approval card instead of running inside the chat turn. This is the new default. A headless or unattended install restores the old behavior with `AGD_ASSISTANT_AUTORUN=true`.
- **`AGD_TLS_VERIFY` is superseded by per-instance `tls_verify`.** The global env var still applies as the default for instances that do not set their own value, but trusting one self-signed box is now a per-instance decision rather than a fleet-wide downgrade. Set `tls_verify` on the instance instead.
- **New rate limits apply to the unauthenticated ingest paths.** The error webhook and the OTLP receiver are now per-IP rate limited via `AGD_INGEST_RATE`, and the public API is per-key rate limited via `AGD_PUBLIC_API_RATE`. Defaults are set well above normal single-fleet traffic; raise them if you front AgeniusDesk with a proxy that collapses client IPs.
- **Silent-failure detection needs OpenTelemetry export.** Instances AgeniusDesk provisions are auto-wired. An instance you connected by URL needs n8n's native OTel export pointed at the dashboard, or the new detection surfaces stay empty. See the README's observability section.

### Added

- **Silent-failure detection (green but broken runs).** n8n reports a run as success even when a node failed under Continue-On-Fail or quietly stopped producing data, so a broken integration hides among the green runs with no failed execution to alert on. AgeniusDesk now catches these on OpenTelemetry ingest by reading output shape rather than status. It unions the three places n8n records a demoted error (the execution status, a run-level error object, and the item-level `json.error` that Continue-On-Fail pushes into normal output, normalized across their inconsistent shapes: an HTTP failure is an object with a status field, a thrown Code error is a bare string), and it classifies each node's output volume against that node's own recent history. A steady producer that had input and dropped to zero, or far below its normal band, is flagged; cold-start nodes and habitually-empty pollers stay quiet (precision over recall, so the alarm stays trustworthy). Drop cascades are suppressed to the origin: a node whose input is itself anomalously low just carried an upstream drop through, so it is a pass-through victim and is not flagged, which keeps one root cause to one alert instead of fifteen. A detected silent failure is written into the same errors pipeline as ordinary errors under its own `Silent failure` class, so it surfaces everywhere at once: a dedicated **Silent Failures** card on the Overview, a matching tile on Insights and the Observe metrics strip, and a `SILENT` badge with jump-to-trace in the Executions / Errors feed. Tunable per instance with `AGD_HEALTH_*` (min-samples floor, steady/dormant zero-rate, drop factor, history window). Detection requires the instance to be exporting OpenTelemetry to AgeniusDesk (auto-wired on provisioned instances). When the instance runs a patched n8n that records the typed continued-error rollup on `taskData.continuation` (the upstream OTel-error-semantics work), detection prefers that **sound** signal (it fires only on a real swallowed error, never on a node that legitimately outputs a field named `error`) and reports the actual error type and count. The unsound item-level `json.error` content-scan is now gated behind `AGD_HEALTH_SCAN_LOOSE_JSON_ERROR`, on by default so stock n8n keeps full recall; turn it off against a patched instance to drop those false positives. Silent runs also render as a distinct amber block on the Overview **Execution Timeline** (each green-but-broken run is pulled out of the success color into its own `Silent error` class), not only the Silent Failures card and the Errors feed. See [docs/architecture/silent-failure-detection.md](docs/architecture/silent-failure-detection.md) and [docs/specs/2026-07-07-silent-failure-detection.md](docs/specs/2026-07-07-silent-failure-detection.md).
- **Dead-man's switch (a node that should have run but didn't).** Extends silent-failure detection to the node that produces no span at all, which the output-shape detectors above cannot see because there is nothing to read. On a completed green run the detector diffs the workflow's declared nodes (from the execution's `workflowData`) against the spans that actually landed. A declared node that had input available (an upstream node produced output) but never ran, and that historically runs in nearly every recent execution of that workflow, is flagged. It is graph-aware, using n8n's connection graph so a node legitimately skipped downstream of an empty node is treated as a cascade victim rather than a dead node, and only the origin fires. Because a missing node has no span to enrich, these surface through the same errors pipeline as the other silent failures (the `Silent failure` class on the Overview, Insights, and the Errors feed). Precision over recall: it fires only on a node with a strong run-history and available input this run, so a conditional branch or an intermittently-run node stays quiet. Configurable with `AGD_HEALTH_DEADMAN_ENABLED` (default on) and `AGD_HEALTH_DEADMAN_MIN_RUN_RATE` (default 0.9). This covers the in-run "a node went missing" case; the other layer, an external heartbeat for a workflow that never fired at all, necessarily lives outside n8n and remains open, now specified in [docs/specs/2026-07-11-heartbeat-dead-mans-switch-layer-2.md](docs/specs/2026-07-11-heartbeat-dead-mans-switch-layer-2.md).
- **Workflow promotion across instances (dev to staging to prod).** A new **Promote** tab and `n8n_promote` module move a workflow from one registered n8n instance to another, the open-source answer to n8n Enterprise environments. A **preflight** runs first and reports, per workflow, every credential the workflow binds, whether the target already ships that credential type, and any duplicate-name collision on the target, so you see what will break before anything is written. **Credential auto-provision** resolves the gap: it reuses a credential AgeniusDesk already mirrored onto the target, or creates one from a matching entry in the Secrets store through the existing credential-mirror path. Ambiguity is never guessed. A credential type with more than one mirror on the target is surfaced as ambiguous and left for you to resolve, and provisioning is idempotent by reuse rather than delete-and-recreate, so an already-promoted (possibly active) workflow never has its credential id yanked out from under it. Auto-provision runs through the same SSRF floor, per-secret instance scope, and URL-repoint checks as the manual mirror route, so a dev-scoped secret cannot be pushed to a prod target. Because n8n binds a node credential by **both** id and name, promotion refuses to activate a workflow whose mapped credential has no name on the target rather than importing something that silently fails at run time, and an activation rejection surfaces n8n's own node-by-node explanation instead of a bare `HTTP 400`. Source and target get a fast liveness probe, so an unreachable or mis-keyed instance fails in about four seconds with a real error rather than an empty workflow picker. Changing the target or the workflow selection invalidates a completed preflight, so you cannot preflight against one instance and promote to another. Endpoints: `GET /api/promote/workflows/{id}`, `POST /api/promote/preflight`, `POST /api/promote/auto-provision`, `POST /api/promote/run`. Ships ungated in CE (operator role). Dogfooded end to end on a live instance. See [docs/guide/promote.md](docs/guide/promote.md).

### Security

- **Assistant tool calls that change state now wait for a click.** The assistant reads content the operator does not control: n8n error and execution payloads, RAG hits, MCP server output. A prompt injection buried in any of those could steer it into a state-changing tool call during an ordinary chat turn, and the call would just run. Those calls no longer execute mid-turn. They come back as a proposal rendered on an approval card, and nothing happens until the operator confirms it (operator-gated, CSRF-checked, single-use, and expiring). The gate lives in a shared `_dispatch_tool`, so it covers both the OpenAI-compatible and the Anthropic tool loops rather than one of them, and the card renders on all six chat surfaces. MCP tools are classified per server (`writes` / `all` / `none`, default `writes`) using the server's own MCP annotations (`readOnlyHint`) with a naming-convention fallback; a tool that cannot be classified fails closed. Classification is verified against the live n8n-mcp 2.59.2 tool list, pinned as a test fixture. Set `AGD_ASSISTANT_AUTORUN` to restore the old unattended behavior for a headless install. Driven by the review and fix plan in [docs/code-review/2026-07-16-full-security-review.md](docs/code-review/2026-07-16-full-security-review.md).
- **Public API keys gain expiry, scoping, and a rate limit.** A key was previously unbounded in time, reach, and call volume. A key can now carry an expiry, be scoped to an IP, an instance, or a workflow, and is subject to a per-key token bucket (`AGD_PUBLIC_API_RATE`), with per-request usage written to the audit trail. Every field is optional and an absent field means unrestricted, so keys you already issued keep working exactly as before.
- **One self-signed n8n no longer disables certificate checking for the whole fleet.** TLS verification moved from a global switch to a per-instance `tls_verify`, so trusting a single box with a self-signed cert stops silently downgrading egress to every other instance. Server-side fetches can additionally be narrowed with `AGD_EGRESS_ALLOW_CIDRS`. Private ranges stay allowed by default, since self-hosted n8n normally lives on one.
- **The unauthenticated ingest paths are rate limited and bounded.** The webhook and OTLP receivers accept traffic without auth by design, which made them the cheapest way to flood the database. Both now enforce a per-IP rate limit (`AGD_INGEST_RATE`), `otel_spans` prunes before it inserts so the configured row cap is a real ceiling rather than a target it overshoots under sustained load, span attributes are size-bounded, and a startup warning fires when the webhooks are left open.
- **Defense-in-depth batch.** A central audit sink; promoted secrets are no longer copied into `os.environ`; bare compound-secret resolution is audited; CORS defaults to same-origin; the MCP ping comparison is constant-time; Docker `HostConfig` is re-checked at deploy time, not only at load; password and TOTP lockout counters are tracked separately so one cannot mask the other; password-reset tokens are rate limited; and the session cookie uses the `__Host-` prefix over HTTPS. Covered by new tests for the tool gate (end to end through the real chat flow), MCP classification against a real server, the public-API / egress / ingest work, and an XSS and contract harness for the approval card.

### Fixed

- **Observed traces are attributed to the instance that produced them, not whoever was active.** n8n's native OpenTelemetry export carries no attribute that names or points at the AgeniusDesk instance it was configured under, only an opaque `n8n.instance.id` hash. The receiver's old matcher never matched that against a configured instance's name or URL, so every trace fell back to *the active instance*. In a multi-instance fleet that silently mis-attributed executions, error rates, and silent-failure counts to whichever instance you happened to be viewing, and it broke cost and silent-failure enrichment outright: enrichment fetched run-data from the active instance's API, which does not hold a foreign instance's execution, so it read empty and wrote **$0 cost / no health**. A real symptom: an LLM workflow's Spend showed `$0.0000` with the Sonnet spans right there in the waterfall. The receiver now resolves each exporter to its instance in two tiers: a deterministic `agd.instance.name` resource attribute stamped on every AgeniusDesk-provisioned n8n (via `OTEL_RESOURCE_ATTRIBUTES`), and, for external or legacy instances, a one-time learn step that resolves the opaque hash by probing each configured instance's API for the trace's execution (confirming the workflow id, since execution ids collide across instances) and pins the hash→instance result so every later trace maps in O(1). An exporter it cannot yet place is parked in a stable `unknown-<hash>` bucket and re-attributed once learned, never dumped onto the active instance. See [docs/architecture/instance-attribution.md](docs/architecture/instance-attribution.md).
- **Cost and silent-failure enrichment fetch run-data from the trace's owning instance.** Both enrichers previously fetched only through the active instance's n8n client, so a trace from any other instance was never priced or health-checked even once correctly attributed. They now fetch through the owning instance's own credentials (the active instance stays the fast path), so cost and silent-failure detection work across the whole observed fleet, not just the one instance in focus.
- **Aggregate Spend counts every run, not just traces you opened.** Cost enrichment ran lazily, only when a trace was opened in the Observe waterfall, while silent-failure (health) enrichment already ran eagerly on ingest. So a finished LLM run left `cost_usd` null on its spans until someone clicked into it, and the Spend metric (which sums `cost_usd` across the window) read near-zero even though each trace priced correctly on open. A full day of runs could show `$0.0000` Spend while any individual waterfall showed real dollars. Ingest now schedules cost enrichment alongside the existing health enrichment for every completed trace (fire-and-forget, using the same bounded run-data fetch and the owning instance's credentials), so a run is priced as soon as it lands and the Spend metric aggregates without anyone opening a trace.
- **Community module views no longer load with dead JavaScript.** Community views render inside a sandboxed iframe with an opaque origin, which makes the view's own `module.js` a cross-origin fetch. The static route did not send an `Access-Control-Allow-Origin` header, so the browser blocked the script silently and the whole view came up with no behavior and no error anyone would notice. `/modules/{id}/static/*` now serves with the header set. Surfaced while debugging the Research view after the sandbox hardening landed.
- **Assistant provider keys resolve however you named your secrets.** Key lookup only checked the convention name (`OPEN_ROUTER_KEY` and friends), so an operator who named the secret anything else got a provider that appeared configured but failed at call time. Resolution now chains the convention name, then any binding set for that provider in the Models area, then the legacy global key. The bridge completion path also resolves its key through the assistant job the way the chat path already did, and it decodes the `provider::model` spec that module UIs send instead of passing the whole string through as a model id.

### Changed

- **Code Lab's default instructions describe the toolset the model actually has.** The old default hedged ("if n8n-mcp tools are available") and never mentioned the built-in deploy and test tools at all, so the assistant tended to hand back a workflow it had neither validated nor run. The new default lays out a concrete build loop: the skill library for how to build, n8n-mcp (`search_templates`, `search_nodes`, `get_node`, `validate_node`, `validate_workflow`) for facts about nodes, and the built-in instance tools (`import_workflow`, `trigger_workflow`, executions) to deploy and test. It drafts from a template first, validates until clean, and activates only when explicitly asked.

## [0.4.4] - 2026-07-06

### Added
- **Scheduled workflow backups.** A new internal interval scheduler runs a best-effort backup job that snapshots every connected instance's workflows to disk under `data/backups/<instance>/`, pruning to a configurable retention. Configure it on the Export / Backup view (enable, interval in hours, snapshots to keep, active-only) or over the new operator-gated `/api/backups` endpoints (`GET/PUT /settings`, `GET` list, `POST /run` to back up now, `GET /{instance}/{file}` download, `DELETE`). The schedule is read live from `config.json`, so toggling it takes effect without a restart, and it fans out across the whole fleet regardless of which instance is active (paginating n8n's cursor so instances with more than 250 workflows back up completely). A failing instance is isolated: the others still snapshot. Off by default.
- **Offsite backup destination (S3-compatible).** Scheduled backups can also push each snapshot to S3-compatible object storage (AWS S3, Cloudflare R2, Backblaze B2, Wasabi, self-hosted MinIO) so a backup survives loss of the host or its Docker volume. Opt-in via a new `s3` dependency extra (minio client; kept out of the default image); enable and configure it under **Offsite destination** on the Export / Backup view, with a **Test connection** probe (`POST /api/backups/test-remote`). The local snapshot is always written first and an upload failure is recorded per instance without losing it. Credentials come only from the encrypted secret store as `$VAR` refs (never stored in config, never returned by the API). Options: mirror the keep-N retention offsite (default on) and Fernet-encrypt the object before upload with the app `SECRET_KEY`. A self-hosted MinIO on the LAN is allowed; the cloud instance-metadata address is refused. Push-only in v1 (restore by downloading the object and using the existing restore drop zone). See [docs/specs/2026-07-06-offsite-backup-s3-sink.md](docs/specs/2026-07-06-offsite-backup-s3-sink.md).

### Changed
- **Local models show token usage instead of "price unknown" in the cost waterfall.** Ollama (and other always-local AI nodes) cost nothing by construction, but the price book had no rate for them so they fell through to the same "unknown" label as a cloud model the book simply hadn't caught up to. Cost enrichment now reads the AI node's `n8n.node.type` off the span and classifies Ollama node types as local (`price_source: "local"`), and the waterfall renders the token counts with a plain "local" tag rather than a dollar figure (the waterfall row shows the total token count in place of a cost). An operator override still pins a real rate if one is set. See [docs/specs/2026-07-02-local-model-cost-clarity.md](docs/specs/2026-07-02-local-model-cost-clarity.md).

The connect form also pre-fills the URL with the host you reached the dashboard by, so accessing AgeniusDesk via a LAN IP auto-fills that IP.

**Onboarding and page tips**
- Setup Journey "Get started" card on the Dashboard. Milestone completion is derived live from app state (n8n connected, secrets added, AI configured, 2FA on, harness visited), so it stays honest and resumable instead of tracking a stored step. Auto-hides once core setup is done; dismissible and reopenable from Settings.
- Page coachmarks: a dependency-free spotlight + bubble walkthrough that runs the first time you open a view, pointing out the key controls (Dashboard, Workflows, Errors, Code Lab, Knowledge, Secrets, Settings, Containers). Tolerates missing anchors, honors `prefers-reduced-motion`, and is keyboard and screen-reader friendly.
- Settings > Help & Tips: toggle page tips, replay the current page's tour, reset all tips, and reopen the setup checklist or wizard. Persistence is per-browser (localStorage).

**Authentication, accounts, and 2FA**
- Built-in login with local accounts. First browser visit forces creation of an owner account (admin), then requires sign-in. The owner account is keyed by **email** (the login identity, also used for recovery); the setup screen spells out the password requirement. Edge identity (Cloudflare Access) can satisfy the gate only when `AGD_TRUST_EDGE_AUTH=true`, and the `AGD_ADMIN_TOKEN` bearer can satisfy the gate when configured.
- Forgot-password flow: a "Forgot password?" link issues a single-use, time-limited reset link to the account email (no account-enumeration in the response). Completing a reset invalidates all other sessions. Delivery uses SMTP (`AGD_SMTP_*`); when SMTP is unconfigured the link is logged so self-hosted installs without a mail server can still recover access.
- Auth bootstrap endpoints (`/setup`, `/login`, `/forgot`, `/reset`) are exempt from the CSRF gate, fixing a first-run failure where a stale `agd_session` cookie (left after a data-volume wipe, or shared across localhost ports) blocked account creation with "CSRF check failed."
- Optional TOTP two-factor (any authenticator app), with one-time recovery codes. QR rendered client-side from a vendored, dependency-free generator; the setup key is also shown for manual entry.
- Server-side sessions stored as a SHA-256 of the token (a DB leak cannot be replayed), `HttpOnly` + `SameSite=Strict` cookie, sliding expiry with an absolute cap, server-side revocation, and a session list in Settings > Account.
- Double-submit CSRF protection on cookie-authenticated mutations.
- Coarse role-based access control (`viewer < operator < admin`): admin/secrets require `admin`; the n8n and container control surfaces require `operator`; read surfaces require any signed-in user. Machine webhooks (errors, messages) stay open for n8n ingestion.
- Password hashing raised to PBKDF2-HMAC-SHA256 at 600k iterations with login-time rehash of legacy hashes; minimum password length raised to 12.
- New settings: `AGD_DISABLE_LOGIN`, `AGD_SESSION_TTL_DAYS`, `AGD_SESSION_ABSOLUTE_DAYS`, `AGD_LOGIN_MAX_ATTEMPTS`, `AGD_LOGIN_LOCKOUT_MINUTES`, `AGD_PASSWORD_MIN_LENGTH`, `AGD_PASSWORD_REQUIRE_*`, `AGD_PASSWORD_RESET_TTL_MINUTES`, `AGD_TRUST_EDGE_AUTH`, `AGD_TRUST_FORWARDED_FOR`, `AGD_WEBHOOK_TOKEN`.
- `harden_file_permissions()` now also `chmod 600`s `users.json` and `dashboard.db`.
